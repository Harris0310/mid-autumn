# 中秋 · 镂空跳动爱心

一个纯静态的中秋祝福页面：**拆开一封白色信封** → 露出一颗**可以转着看的
3D 镂空跳动爱心** + **满屏飞过的粉色祝福语** → 飘满九秒，**信纸升起，是一封信**。
无构建、无依赖，双击 `index.html` 即可运行。

## 本地看效果（开发用）

双击 `index.html` 即可。个别浏览器对 `file://` 有限制时，才需要起一个临时静态服务：

```bash
python -m http.server 8080   # 然后访问 http://localhost:8080
```

调试用：网址后加 `?t=秒` 可把画面冻结在第 N 秒，方便截图核对
（`?t=1.2` 看爱心、`?t=12` 看信）。整条时间轴：拆封 1.9s → 信息流 9s → 信 2s。

## 开场信封

打开链接先是**一封白色信封**，正中一枚爱心封蜡，下面一行字
「有一份中秋节礼物等待查收」。**轻触屏幕任意位置**即可拆封：

1. 封蜡爱心放大淡出（"破封"）
2. 封盖绕上边缘翻开
3. 信纸从里面升起来
4. 整封信放大淡出，同时主场景从中心长出来

封盖的翻开没有用真 3D，而是「绕上边缘旋转」的投影：三角形顶点相对上边缘的
偏移量乘以 `cos(角度)`。角度从 0 转到 π，偏移就由 `+flapH` 经 0 变成
`-flapH` —— 正好是"先压平、再向上翻起"。

文案、信封尺寸、各段时间轴都在 `js/config.js` 的 `envelope` 段里。
不想要信封就把 `envelope.enabled` 设成 `false`，会直接进爱心场景。
想让某个链接跳过信封，网址后加 `?open=1`。

## 信

祝福语飘满 `letter.flowSeconds` 秒（默认 **9 秒**，长长久久）之后，信息流用
最后 `flowFade` 秒淡出，接着**信纸从屏幕下方自动升起**，上面是一封写给她本人的信。

**正文一百多字，整封一屏放下**——字号是**自动试出来的**：从 `letter.maxSize`
往下试，每档都断一次行、量一遍总高度，第一个装得下的就是最终字号
（手机上 16px、桌面 24px）。所以改文案不用管排版，它自己会缩。

称呼（`greeting`）用粉色，正文两段带**首行缩进**；信纸顶部一枚小 ♥ 封记。
断行是自己写的：中文任意处可断，英文单词尽量整词挪到下一行，不会把
`love` 劈成两半。

| 位置 | 作用 |
| --- | --- |
| `letter.flowSeconds` | ★ 信息流持续几秒（默认 9） |
| `letter.flowFade` | 最后几秒用来淡出 |
| `letter.duration` | 信纸升起的动画时长 |
| `letter.greeting` / `letter.body` | 称呼与正文段落 |
| `letter.indent` | 段落首行缩进几个字 |
| `letter.maxSize` / `minSize` | 自动排版的字号上下限 |
| `letter.paperW` / `paperMaxW` / `paperH` / `paperRatio` | 信纸尺寸 |
| `letter.maxSize` / `lineHeight` / `paraGap` | 排版密度 |
| `letter.seal` | 信纸顶部的小封记，改成空串就不显示 |
| `letter.veil` | 信升起时背后的爱心压暗到什么程度 |
| `letter.enabled` | 设 `false` 就没有信这一段（飘完信息流就停在爱心上） |

> 系统的「减少动态效果」打开时，整页不做动画，**直接显示这封信**。

## 3D 与视角

爱心是一颗**真正立体的、中空的心**：每个粒子在 2D 轮廓的基础上还带一个 z，
半厚度 `T(s) = thickness · √(1 − s²)` —— 中心最厚、到轮廓收到 0。所以正面看
仍是原来那颗镂空的心，转起来才看得出是一颗有厚度的心形。

**用手指或鼠标拖动**即可转动：

| 操作 | 效果 |
| --- | --- |
| 上下拖 | 俯仰（上下视角），限位 ±66° |
| 左右拖 | 偏航（左右视角），限位 ±83° |
| 松手 | 带惯性继续转一会儿再停 |
| 静止 1.5 秒后 | 自己缓慢左右摆动，暗示这是立体的 |

手感反了的话，把 `js/config.js` 里 `orbit.invertPitch` / `orbit.invertYaw`
改成 `true` 即可。手机上拖动不会触发页面下拉刷新（`touch-action: none`）。

## 改文案

**只需要改 `js/config.js` 里的 `text.scroll.pool`**，那是一组句子。页面会不断从
池子里随机抽句子发射出去 —— 每一条都在**随机的位置**（横向全宽随机、纵向从屏幕
下方随机）、**随机的时刻**出现，带着**随机字号**（近大远小）向上飘，
**0.75 秒穿过一屏**后淡出。所以同一眼看到的版式永远不一样，是"信息流"的味道。

```js
pool: [
  '想从你的窗子里看月亮',
  '中秋节快乐，猫猫婷♥',
  /* ... */
],
```

> 池子里的句子越多，"重复感"越低；句长不必统一（长句子会自动缩一点字号，
> 保证不顶出屏幕）。页面会**优先挑此刻屏上还没有的句子**，所以只要池子比屏上
> 的条数多（手机约 24 条），看到的基本都是新句子；池子太小时重复是数学上不可
> 避免的。现在池子里是 6 句、屏上 24 条，同一句同时出现三四次是必然的。

**所有文案的上升速度完全一致**，所以版式一旦撒好就永不改变 —— 随机但不混乱，
绝不会互相追上或压在一起。另外还有一道**出生避让**：新文案若和屏上已有的撞上，
会自动换个位置重试；实在挤不下就先不发，等下一帧 —— 所以"不压字"是结构上的
保证，密度会自动收敛到"塞得下的最大值"。

想调快/调慢、调密/调疏，先看这两个旋钮（都在 `text.scroll`）：

| 旋钮 | 作用 |
| --- | --- |
| `crossSeconds` | ★ **速度**：一条文案从屏幕底穿到顶用几秒。当前 `0.75`（截图实测 0.76 秒/屏）；`1.0` 偏慢、`0.5` 快到看不清。 |
| `density` | **密度**：屏上同时大约几条。当前 `24`（手机视口；大屏按面积自动放大，上限 2.2 倍）。 |

其余可调项（都有中文注释）：

| 位置 | 作用 |
| --- | --- |
| `text.scroll.size` / `minViewportRatio` / `maxSize` | 基准字号及其上下限（保证手机上不缩成看不清的小字） |
| `text.scroll.sizeMin` / `sizeMax` / `sizeSteps` | 字号随机区间与量化档数（近大远小；量化是为了让字形缓存能命中） |
| `text.scroll.maxWidthRatio` | 单条文案最多占屏宽多少（长句自动缩字号，也让高密度下排得开） |
| `text.scroll.farAlpha` | 小字（远处的字）压暗到什么程度 |
| `text.scroll.spawnTopRatio` | 出生带的下沿。越接近 1 越是从底部涌上来、整屏密度越均匀 |
| `text.scroll.edgeBleed` | 允许文字超出屏幕边缘多少（贴边的字更有"满屏"感） |
| `text.scroll.placeTries` / `placePad` | 出生避让的重试次数与要求的最小间距（密度调高时要一起加） |
| `text.scroll.fadeIn` / `fadeOut` / `alpha` | 淡入淡出距离与峰值不透明度 |
| `text.scroll.color / highlight / glow` | 粉色底色、流光高光、发光 |
| `text.scroll.glowMinMul` | 多大的字才给发光（小字不给，省性能） |
| `text.scroll.sheen` | 关掉就退回纯色填充（省掉流光） |
| `heart.beat.mode` | `'classic'` 原版匀强正弦 / `'pulse'` 仿真双脉冲 |
| `heart.beat.period` / `amplitude` | 搏动周期与幅度（原版 1.2566s、0.05，想更猛就调大） |
| `heart.beat.jitter` | 逐点抖动强度，设 0 关闭以省性能 |
| `heart.enlarge` / `layers` / `profile` | 爱心大小、粒子密度、镂空程度与配色 |
| `heart.colorStops` | 配色分档。想试"完全不掺粉的纯中国红"就改成 `[0, 0, 0.02]` |
| `heart.cx` / `cy` | 爱心在设计画布中的位置 |
| `envelope.enabled` | 关掉就跳过信封直接进爱心 |
| `envelope.text` | 信封上那行字 |
| `envelope.duration` / `sealPhase` / `flapStart` / `flapEnd` | 拆封节奏 |
| `envelope.exitStart` / `exitScale` / `revealStart` | 淡出与主场景显现的时机 |
| `heart.depth.thickness` | 3D 半厚度：调大更"胖"，0 就退回平面 |
| `heart.depth.perspective` | 透视焦距，调小透视更夸张 |
| `heart.depth.bands` / `backAlpha` | 深度分档数与背面暗度（前后层次） |
| `orbit.enabled` | 关掉就完全不响应拖动 |
| `orbit.*Sensitivity` / `maxPitch` / `maxYaw` | 转动灵敏度与限位 |
| `orbit.inertia` | 惯性衰减，越接近 1 转得越久 |
| `ambient.*` | 背景星点与金色微尘 |
| `seed` | 随机种子，换一个就是另一颗心 |

## 实现要点

- **配色以中国红为主体**（对齐 `heart.cpp` 的 `RGB(255,33,33)`）。
  注意这**不是** `heart_particle.cpp` 里那套深红 —— 那套（主体 R 只有 76~152）
  是从一张暗调参考图实测的，放到纯黑背景上会发灰发闷，看不出原版那种
  "亮红实心"的劲儿。
- **镂空**：粒子按「径向密度剖面」布点 —— 中心极稀、约七成半径处最浓、
  最外圈转淡，再叠一层沿轮廓法线抖动的毛边和一层空腔雾点。
- **密度归一化**用「自形心的射线归一化」`s = |p−形心| / R(θ)`，
  保证等密度线严格贴合心形，顶部裂口与底部心尖不会被压歪。
- **3D 完全在 JS 里逐点算**：按心跳放大 → 绕 Y 轴（左右）→ 绕 X 轴（上下）
  → 透视除法。粒子按深度分成 `bands` 档、**由远及近**绘制，最远一档压低
  透明度，于是前后有层次、近处粒子自然盖住远处。没有用 WebGL，也没有
  引入任何 3D 库。
- **空腔雾点只铺在厚度中间薄薄一层**（`depth.hazeSpread`）：铺满整个厚度的话，
  一转起来正面与背面重叠，会把"镂空"糊成实心。
- **心跳**用回原版 `heart.cpp` 的匀强正弦 `ratio = 15·sin(frame·0.1)`：
  ω = 5 rad/s、周期 2π/5 ≈ 1.26 秒，正负对称、中间不停顿，等幅一下一下
  很实 —— 不写实，但浪漫。原版的力场位移 `|d| = ratio / r^0.04` 在
  整个半径范围内几乎是常数，等价于约 ±5% 的等比缩放，所以这里直接用一个
  缩放矩阵表达。
- **逐点抖动** `rand()%3-1`（`heart.beat.jitter`）：原版每帧给每个点加
  随机偏移，整颗心持续"沸腾"，搏动时才不像一张放大的静态图 —— 这是力量感
  的一部分。设为 0 可回到"坐标全静态、每帧只改一个缩放矩阵"的零开销路径。
- **另一个节奏** `heart.beat.mode = 'pulse'` 保留着仿真心音的双脉冲
  （强搏动 + 弱搏动 + 舒张期），更写实但力量感弱，随时可切。
- **字幕是"发射器"**而不是"一列滚动"：按固定速率不断随机发射一条文案，
  每条记住自己的字号 / 横向落点 / 出生高度 / 生命，飘出屏幕就回收
  （对象进回收池复用，避免每秒十几次分配）。
  随机来自三处 —— 出生态（速率均匀）、横向落点（全宽随机）、字号（近大远小）；
  **速度全场一致**，所以撒好的版式会原样保持到飘出屏幕，永不追尾、不压字。
- **密度与速度解耦**：`crossSeconds` 只管快慢，`density` 只管屏上几条。
  发射速率由"屏上想同时看到几条 ÷ 平均在屏时间"反推，所以调快不会顺带把
  屏幕塞满。
- **为什么出生带贴着屏幕下方**：只向上飘的话，在高度 y 处的密度正比于
  "出生点在 y 以下"的比例，所以出生带越高、下半屏越空。想整屏密度均匀，
  出生点就必须贴着底边；"随机出现的位置"由横向全宽 + 随机字号 + 随机时刻
  来给，而不是靠把字凭空撒在半空。
- **出生避让**：满屏撒字很容易两句话压在一起（同一句还会看起来像重影），
  所以每个新文案随机试 `placeTries` 个位置，取第一个和屏上已有文案不重叠的；
  **一个都让不开就先不发**，把额度留给下一帧 —— 于是"不压字"是结构上的保证，
  屏上条数会自动收敛到"塞得下的最大值"，而不是靠调参调出来的。
- **性能上的三个小机关**：字号量化成 `sizeSteps` 档（字号完全连续的话，
  每条文案的字形都得重新栅格化，浏览器的字形缓存永远打不中）；
  发光只给够大的字（`glowMinMul`，逐个字形做高斯模糊是软件渲染下最大的一笔
  开销）；流光的渐变按量化相位缓存复用（少掉每帧十几条颜色字符串的分配）。
- **信的字号是自动试出来的**：从 `maxSize` 往下试，每档断一次行、量一遍总高度，
  第一个装得下的就是最终字号 —— 改文案不用管排版。
- **信纸缓存成一张离屏位图**：信纸 + 投影是静态的，而每帧对一块 335×500 的
  圆角矩形做一次 30px 高斯模糊，软件渲染下要 16ms 以上（实测掉到 30fps）。
  缓存之后这一段的帧时中位从 33.3ms 回到 16.7ms。
- **信升到顶之后不再画爱心**：爱心在暗纱下面本来就看不见了（有截图为证），
  省掉每帧 8650 个粒子 + 满屏星点。所以最后停在信上时是稳稳的 60fps。

## 性能（真实浏览器实测）

用 `_dev/browsercheck.js` 走 DevTools 协议在 Edge headless 里实测，
而且刻意**强制软件渲染**（`--disable-gpu`），也就是最坏情况。
报的是**帧时**而不是平均帧率 —— 均值会被个别长帧（GC / 合成）带偏，
所以同时给中位数和 p90：

| 场景 | 帧时中位 | p90 | 平均 | 说明 |
| --- | --- | --- | --- | --- |
| 手机 390×844（画布 dpr 上限 2）信息流 | 16.7 ms | 16.7 ms | 57.6 fps | 屏上 24 条；均值被个别 33ms 帧拉低 |
| 手机 信升起之后 | 16.7 ms | 16.7 ms | 60.0 fps | 最慢一帧也只有 16.8ms，零掉帧 |
| 桌面 1440×900 信 | 16.7 ms | 16.7 ms | 60.0 fps | 同上 |
| 桌面 1440×900 信息流 | 16.7 ms | 16.8 ms | 59.2 fps | 条数按面积放大到 52 条 |

速度也是实测的，不是照代码推的：`_dev/browsercheck.js` 会跟着一条文案走 1.2 秒，
量它实际飘了多少像素 —— 最近一次是 **1110 px/s，折算 0.76 秒穿完一屏**
（配置里写的是 0.75）。

**爱心单独跑是零掉帧的**（中位 16.7 / p90 16.7，从第一秒起就稳），
加上满屏字幕之后才刚好贴着 60fps 的预算 —— 所以字幕的发光/流光就是
这个页面最贵的地方。`_dev/perfprobe.js` 可以逐个关掉它们看各自吃掉多少帧时：

```bash
node _dev/perfprobe.js 3              # 3 = 对齐 browsercheck 的 deviceScaleFactor
node _dev/perfprobe.js 3 tap          # 走完整流程（信封 -> 拆封 -> 主场景）
node _dev/perfprobe.js 3 tap noflow   # 只量爱心（字幕的对照基线）
node _dev/perfprobe.js 3 tap "F.sc.glowMinMul=1.5"   # 试参数，看冷启动余量
```

真机有 GPU，这一档开销基本不在关键路径上；但真要再省，这些旋钮有效
（都在 `js/config.js`）：

| 旋钮 | 做法 |
| --- | --- |
| `text.scroll.glowMinMul` | 调到 `1.5` 就只有最大的字发光，省掉大半模糊开销 |
| `text.scroll.sheen` | 设为 `false`，退回纯色填充（省掉流光渐变） |
| `text.scroll.glowBlur` | 调小（如 `10`），模糊半径小、开销按面积降 |
| `text.scroll.density` | 条数减半，观感几乎不变（本来就不会压字） |
| `heart.beat.jitter` | 设为 `0`，省掉每帧 8650 次随机抖动的路径重建 |
| `heart.depth.bands` | 从 3 降到 2，`fill()` 调用次数直接少三分之一 |
| `heart.layers` | 三个粒子层数量各减三到四成（观感几乎不变） |
